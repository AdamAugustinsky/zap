## Not `sys`'s rows, but built here

- **File panels (`PickRequest`).** The core's request for files, a folder or a save place shows the system's open or save sheet on the main window and the choice goes back (`PickAnswer`); a cancelled panel or one that cannot be shown answers with no paths, so the core never waits. Tests: `TestAFilePickIsAnOpenPanelAndTheChoiceGoesBackToTheCore`, `TestOneFileAFolderAndASavePlace`, `TestACancelledOrUnshownPanelAnswersWithNoPaths`, `TestAPanelNotOursIsLeftAlone`. This is what CP-013 (`ui/composer`, hand) relies on; hand: Send files in a chat opens the sheet, and picking two files stages both. Panels read their results from `App.TakeDialog`, which has no way to look before taking: if another package starts using `App.Alert` or the panels, results can cross.
- **LN-003** (`ui/composer`): `sys` sets `s.Req.Prefill` through `a.StartChat`; the composer takes it.

## Idle wakeups

`sys` has no timer, ticker or polling goroutine. A second launch's request is announced by `instance.Options.Notify` with an app post, so an idle copy, window or not, wakes for nothing of `sys`'s. The 2 s ticker (0.5 wakeups a second in a non-demo run, measured by the budgets agent) is gone; the demo never had it (the demo takes no instance). Not re-measured live: that needs a non-demo run, which opens a real account's folders.
