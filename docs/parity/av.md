# Parity: ui/conversation/av

`docs/PARITY.md` holds the status of record for every row; this file holds the evidence (tests, captures, hand steps and notes).

The rows of `docs/PARITY.md` that `ui/conversation/av` implements: voice notes and audio files, inline videos, GIF videos, round video notes and motion photos' clips inside the transcript's bubbles, and their playback on `media.Player` and `media.Video`. Tests are in `gnui/ui/conversation/av`. The live tests (`AV_LIVE=1`) use the demo core and the real players. With `AV_SHOT=<dir>` the tests write the captures named below.

Status values: **done**, **partial**, **todo**, **waived** (with the reason) and **hand** (implemented, and checked only by hand).

MK-013 close-out also ran `TestLiveGIFPausesWhenHidden` with the real macOS
`media.Video`, muted, on the synthetic demo MP4: playing frames allocate zero,
and hiding the window with its block unbuilt stops playback and requests no
frames. The inspected `real-gif-playing.png` capture is emitted by `AV_SHOT`.
`TestGIFRemovedFromTheTranscriptSchedulesItsPause` additionally verifies the
event-driven handoff: the ticker keeps the last video deadline for one frame
when Build omits the block, so the next ticker actually gets to pause it.
Without that wake the player continued while the UI had no frame owed.
The inline-video sibling now follows the same hidden/unbuilt ticker rule;
`TestInlineVideoHiddenOrRemovedPausesWithoutFurtherInput` failed in both states
before the fix and passes afterward. The demo transcript checks the GIF button,
not the length chip that upstream hides once a frame is decoded.

## Not here

- **The viewer's video** (VW-009, VW-010, and resuming MK-016's clip at `Win.ViewerAt`): ui/viewer.
- **Other apps' media held while a clip plays**: `av.Playing()` reports a voice note, an audio file or a clip playing with its sound. Nothing reads it yet. That is the shell's or sys's to wire.
